The metering layer, build this first

This is the bridge from the cost model to a real invoice. Every number in the calculator assumes it exists.

PieceRole
Durable Object per customerholds the live usage counter, one per tenant
On each API or AI callincrement the counter, check it against the plan cap
At the capblock, or allow metered overage per the plan
Periodicallyflush usage to D1 and to Stripe for billing
Dashboardreads D1 for the customer usage and the cost to serve them

Recommended build sequence

1
Scaffold
Workers, D1, R2, KV, Queues, AI Gateway, Better Auth, customer API keys. The skeleton runs on a branch with a PR.
2
Metering and quotas
The Durable Object per tenant, the plan limits, block at the cap. Usage is counted and capped.
3
Routing and billing
Cheap path versus AI path, cache first, Stripe metered billing with overage. Revenue flows.
4
Research and observability
The scraping engine on Hetzner with residential proxy, Sentry plus per tenant cost attribution.
5
Compliance, DX, launch
GDPR documents and the scraping legality call, API docs and an SDK, then ship and push the one GTM channel.

What the 2026 market says

ModelHybrid base plus metered credits is the default for AI native products. Pure flat pricing is dying.
MarginsAI compresses SaaS gross margins from 80 to 90 percent down to 50 to 60 percent. Target 60 to 75 percent with caching and cheap model routing.
CreditsCredit based pricing is becoming standard. One credit maps to an API call or an AI action.
Outcome pricingCharging per completed job, not per access, unlocks 5 to 10x more revenue. Consider it for the AI path.
SignalGitHub Copilot moved to usage based billing in June 2026. Heavy AI users must be metered.
